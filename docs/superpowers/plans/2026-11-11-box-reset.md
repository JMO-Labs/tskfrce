# Box reset implementation plan (PR 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let parents reset the app (wipe family data, keep Wi-Fi/box ID/telemetry) or factory reset (also forget Wi-Fi, re-arm sticker), with backup export, forgot-PIN recovery, and CLI entry point for locked-out parents.

**Architecture:**
- **Reset app:** wipes kids, chores, devices, history, parent PIN. Keeps Wi-Fi saved, box ID/secret/domain, UPDATE_CHANNEL, telemetry config.
- **Factory reset:** also wipes saved Wi-Fi via `sudo systemctl restart systemd-networkd` (no NetworkManager on beta), re-arms sticker claim code.
- **Order:** flush blocker nftables rules (unblock all) → wipe data → restart box.
- **Entry points:** Settings API (parent PIN + typed `RESET` confirm), `sudo tskfrce-reset [--factory]` CLI, forgot-PIN login recovery (sticker code).
- **Backup:** JSON export endpoint (family data, no secrets or parent PIN).
- **Telemetry:** eval boxes send `box_reset` event (check `TASK4CE_TAG` env var).

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, pytest; bash for install.sh. No frontend code (mockups only).

**Spec:** `docs/superpowers/specs/2026-11-11-box-lifecycle-design.md` (PR 2 section). All decisions owner-approved 2026-11-11.

## Global Constraints

- Blocker: POST `BLOCKER_URL/state` with `{"blocked": []}` to flush all rules (unblock all devices).
- Parent PIN: use existing password auth; compare in constant time on forgot-PIN sticker code entry.
- Claim code: reuse `app/core/claim.py` (normalize, hmac.compare_digest, ALPHABET).
- Wi-Fi keep: box ID, secret, domain. UPDATE_CHANNEL and telemetry config stay in `.env`.
- DB wipe: delete all from kids, chores, devices, chore_runs, device_notifications, points, rewards, inbox, assignments. Keep users (parent), family_settings, family_keys. Migration after head.
- Eval telemetry: send if `TASK4CE_TAG` starts with `eval-`.
- CLI: bash script `scripts/tskfrce-reset`, installed by install.sh, callable as `sudo tskfrce-reset [--factory]`.
- Rate limit: sticker code attempts use existing claim-code lockout (5/min/IP, backoff 60–3600 s).
- Auth tests: 401 for kid session, 403 for unauthenticated user.
- Mockups at `docs/mockups/box-lifecycle/reset.html` (both levels, backup, confirm) and `forgot-pin.html` (login variant). Match v3 parent UI style. Owner approval required before merging.
- Keep files under 500 lines. Use semantic commits. Version unset (PR 1 owns next bump). Ruff clean on all changes.

## Review Focus

1. **Blocker unreachable:** reset proceeds (fail-safe), logs warning. Existing rules remain, devices not unblocked until blocker recovers.
2. **Sticker code wrong:** 5 attempts, then lockout doubles (60, 120, 240 s). Each correct attempt in wrong window is a guess (same as claim). Fresh box has no code.
3. **Factory reset on IP-mode box:** Wi-Fi has no NetworkManager; `systemctl restart systemd-networkd` is a no-op (safe). Sticker claim code re-armed.
4. **Reset mid-session:** if a kid is in an active session, the reset is blocked with a 409. Parent must end the session first (existing API).
5. **Eval telemetry:** the event is sent async, never blocks the reset. If Umami is unreachable, reset completes anyway.
6. **Backup export:** JSON has family name, kids (no devices yet), chores, rewards, points history (sanitized, no PII). Parent can save before wiping.
7. **Password verify fails:** reset endpoint returns 401 or 403 (401 for no auth, 403 for wrong PIN). Typed confirm must match exactly (case-sensitive `RESET`).
