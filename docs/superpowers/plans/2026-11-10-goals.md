# Goals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kids save points toward their own and family goals, parents price and fulfill them, and a mascot party plays when a goal comes true.

**Architecture:** Four new tables (`goals`, `goal_contributions`, `goal_auto`, `goal_parties`) plus goal columns on `family_settings`. One service owns all point movement under `economy.SPEND_LOCK`, writing `Points` ledger rows (TRANSFER, reasons `goal_save`/`goal_return`), so balance stays `SUM(amount)`. Parent API `/api/v1/goals`, kid API `/api/v1/kid/goals`. Frontend: a Goals item in Kids & chores → Rewards, "My goals" in the kid Rewards tab, and a party overlay in `KidApp`.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, pytest; Next.js/React/TS, TanStack Query, jest.

**Spec:** `docs/superpowers/specs/2026-11-10-goals-design.md`. Read its "Builder's calls" section, which holds the exact rules. Mockup: `.superpowers/mockups/goals-v1.html`, which is binding for look, classes and colors.

## Data model (Task 1 creates it; everyone else consumes it)

`goals`: `id`, `name` String(60), `emoji` String(16) null, `kind` String(6) CHECK in (`custom`,`screen`,`jail`), `kid_id` FK users null (null = family goal), `target` int null (null only while suggested), `minutes` int null (screen only), `status` String(9) CHECK in (`suggested`,`active`,`full`,`fulfilled`), `created_by_id` FK users, `owner_id` FK users null (the parent named in "Waiting on …"), `created_at`, `reached_at` null, `fulfilled_at` null, `fulfilled_by_id` null.

`goal_contributions`: `id`, `goal_id` FK cascade, `kid_id` FK null (null = parent chip-in or penalty take), `by_id` FK null, `amount` int (signed), `kind` String(7) CHECK in (`save`,`auto`,`return`,`chip_in`,`take`), `note` String(120) null, `created_at`. A goal's saved amount is `SUM(amount)`.

`goal_auto`: `kid_id` PK FK cascade, `goal_id` FK cascade. This is the kid's chosen auto-share goal.

`goal_parties`: PK(`goal_id`,`kid_id`), `seen_at` null.

`family_settings` gains: `goals_on` bool default 1, `goal_suggest` 1, `goal_withdraw` 1, `goal_siblings` 0, `goal_auto` 0 (0 means by hand), `goal_auto_pct` int 25, `goal_max_little` 1, `goal_max_kid` 2, `goal_max_teen` 3, `goal_screen_on` 0, `goal_screen_price` 200, `goal_screen_minutes` 60, `goal_jail_on` 0, `goal_jail_price` 500.

`points.reason` CHECK adds `goal_save`, `goal_return`. `notifications.kind` CHECK adds `goal_full`, `goal_suggested`, `jail_card`.

## API contract (backend Tasks 3–4 produce it; frontend Tasks 5–9 consume it)

Goal JSON (`GoalOut`):
`{id, name, emoji, kind, family: bool, kid_id, kid_name, target, saved, minutes, status, waiting_on: str|null, mine: int, siblings: [{name, amount}]|null, created_at, fulfilled_at}`
- `mine` is what the viewing kid gave. It is 0 for parents.
- `siblings` is null unless `goal_siblings` is on (kid view). The parent view always gets the list.

Settings JSON (`GoalSettings`): `{on, suggest, withdraw, siblings, auto, auto_pct, max_little, max_kid, max_teen, screen_on, screen_price, screen_minutes, jail_on, jail_price, screen_ok: bool}`. `screen_ok` is read-only and true while banking is active.

Parent (all `require_parent`):
- `GET /api/v1/goals` → `{settings, waiting: GoalOut[] (full + suggested), family: GoalOut[], kids: GoalOut[] (active), done: GoalOut[] (last 10 fulfilled)}`
- `POST /api/v1/goals` body `{name, emoji?, target, kind='custom', kid_ids: int[], family: bool}` → GoalOut[] (one per kid, or one family goal). `kind` `screen`/`jail` takes name, target and minutes from settings and needs that built-in on. A family goal must be `custom`.
- `PATCH /api/v1/goals/{id}` `{name?, emoji?, target?}` → GoalOut. A changed target re-checks full or active.
- `DELETE /api/v1/goals/{id}` → 204. Returns points to every kid. 409 if fulfilled.
- `POST /api/v1/goals/{id}/price` `{target}` → GoalOut (suggested → active, sets owner).
- `POST /api/v1/goals/{id}/decline` → 204 (deletes a suggestion).
- `POST /api/v1/goals/{id}/fulfill` → GoalOut (full → fulfilled; 409 otherwise).
- `POST /api/v1/goals/{id}/chip-in` `{amount>0}` → GoalOut (family goals only).
- `GET /api/v1/goals/settings` → GoalSettings; `PATCH` same shape, partial → GoalSettings.

Kid (GET uses `view_kid`, writes use `require_kid`; a kid may only touch own goals or family goals):
- `GET /api/v1/kid/goals` → `{on, suggest, withdraw, auto, auto_pct, auto_goal_id, can_add: bool, free: int, builtins: [{kind, name, target, minutes}], goals: GoalOut[] (own suggested/active/full + family active/full), done: GoalOut[] (last 5), party: [{goal_id, name, by}]}`. When `on` is false: `goals`, `party` and `builtins` are empty.
- `POST /kid/goals/suggest` `{name}` → GoalOut
- `POST /kid/goals/start` `{kind: 'screen'|'jail'}` → GoalOut
- `POST /kid/goals/{id}/add` `{amount>0}` → GoalOut
- `POST /kid/goals/{id}/withdraw` `{amount>0}` → GoalOut
- `POST /kid/goals/{id}/auto` → 204
- `DELETE /kid/goals/{id}` → 204
- `POST /kid/goals/{id}/party-seen` → 204

Errors are `HTTPException` with kid-readable copy, for example `"You can have 2 goals at a time."`, `"You have 40 points to spare."`, `"Goals that are full stay put until a parent says it's done."`, `"Points in a family goal stay there."`, `"A parent turned off taking points back."`.

`NeedsItem` additions (from `/today`'s `needs_you`): `{type: 'goal_full'|'goal_suggested', id: goal id, kid_id, kid_name, title: goal name, cost: target, submitted_at: reached_at or created_at}`. A family goal has `kid_id` null.

## Review Focus

1. **Two taps of "+ Add" at once with exactly enough points.** Only one succeeds. Neither save makes the balance negative or overfills (SPEND_LOCK and re-read inside the lock). Test in Task 2: `test_save_never_overdraws`.
2. **Pending reward requests hold points.** A save can't use points held by pending redemptions (`balance - pending_cost`). Test in Task 2: `test_save_respects_held_points`.
3. **The parent lowers the price below what's saved.** The goal turns full, the parent is notified once, and the surplus stays (no refund). Raising the price again sets it back to active. Test in Task 3: `test_patch_target_below_saved_marks_full`.
4. **A family goal is deleted after three kids gave.** Each kid gets back exactly their own net amount. Parent chip-ins vanish. Test in Task 2: `test_delete_family_returns_each_kid`.
5. **Auto-share when the goal is nearly full, or Goals off, or the kid's goal was deleted.** The share is capped at the remaining amount, nothing moves when off, and the fallback is the oldest active goal. Test in Task 4: `test_auto_share_caps_and_fallbacks`.

### Task 2: Goals service (point movement)

**Files:**
- Create: `backend/app/services/goals.py` (under 300 lines)
- Test: `backend/tests/test_goals_service.py`

**Interfaces (Produces):**
- `saved(db, goal_id) -> int`, `given(db, goal_id, kid_id) -> int`
- `max_for(fam, kid: User) -> int` (reads the age mode)
- `own_count(db, kid_id) -> int` (suggested + active + full own goals)
- `save(db, goal: Goal, kid: User, amount: int, kind='save') -> int`: moves `min(amount, remaining)`. Raises 409 when `amount > balance - pending_cost`. Writes a Points row (`TRANSFER`, `-n`, reason `goal_save`, description `f"Saved to {goal.name}"`) and a contribution. Calls `_check_full`. Commits.
- `withdraw(db, goal, kid, amount) -> int`: errors for family, full, setting off, or more than given. Writes a `goal_return` Points row and a negative contribution. Commits.
- `chip_in(db, goal, parent, amount) -> int`: family goals only; no ledger row. Commits.
- `refund_all(db, goal) -> None`: each kid gets back `given(...)` if > 0 via `goal_return`. Flushes only.
- `delete(db, goal) -> None`: refund_all then delete. Commits.
- `set_target(db, goal, target) -> None`: calls `_check_full`, which goes both ways.
- `_check_full(db, goal)`: active and saved ≥ target → full, `reached_at`, `inbox.notify_parents(db, "goal_full", f"{who}'s {goal.name} is full", ...)` where who = kid name or "The family". Full and saved < target → active.
- `fulfill(db, goal, parent) -> None`: 409 unless full. Sets fulfilled, `fulfilled_by_id`, `fulfilled_at`, then adds `GoalParty` rows (kid goal → that kid; family goal → every kid). `kind=='screen'` → `grant_screen(db, kid_id, goal.minutes)`. Commits.
- `grant_screen(db, kid_id, minutes) -> None`: adds the minutes to `ScreenBank.minutes` (creates the row if missing).
- `waiting_on(db, goal) -> str|None`: the owner parent's `full_name or username`, falling back to the family owner.
