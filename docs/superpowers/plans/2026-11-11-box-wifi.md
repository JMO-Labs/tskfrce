# Box Wi-Fi setup and management — implementation plan (PR 3 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable a parent to set up home Wi-Fi during initial box setup via a captive portal, with hotspot fallback, country code handling, and Settings → Wi-Fi to change networks with 60s rollback protection.

**Architecture:**
- **Privileged: systemd service** (`tskfrce-wifi.service`) runs a small Go or shell-based nmcli wrapper on the host (outside compose). Communicates with the backend via a Unix socket at `/run/tskfrce-wifi.sock`.
- **Setup mode:** triggered by no wired DHCP lease + no saved Wi-Fi at boot, or saved Wi-Fi unreachable for 5 minutes.
  - Scan networks first (single-radio limitation).
  - Start hotspot `t@sk4ce-<first4>` (WPA2, 2.4 GHz channel 6, password from image).
  - Serve captive portal (DNS spoofing + HTTP page).
  - On "Connect": live join while hotspot stays up (concurrent mode). If join fails in 60s, bring hotspot back.
- **Country code:** hotspot always starts as `US`. Once online, read `CF-IPCountry` from domain service IP-report reply header. Persist to `.env`, then `iw reg set`. IP-mode boxes get a Settings country dropdown.
- **Wi-Fi API:** FastAPI routes at `/api/network/wifi/scan`, `/api/network/wifi/join`, `/api/network/wifi/status`.
- **Forget Wi-Fi:** exposed as a CLI command `tskfrce-wifi-forget` (shell script calling the service).

**Tech Stack:** nmcli (via NetworkManager), nftables (captive DNS), Python FastAPI, Unix socket IPC.

**Spec:** `docs/superpowers/specs/2026-11-11-box-lifecycle-design.md` § PR 3 and `docs/superpowers/specs/2026-11-04-easy-onboarding-design.md` § 2–3 (binding).

## Global Constraints

- **No hostapd, no dnsmasq.** All via nmcli and nftables.
- **Wired eno2 lifeline.** Switch renderer while eno2 has a lease.
- **Idle scan cache.** Before starting hotspot, scan once and cache the results. Skip scan while in hotspot mode (single-radio chip can't scan while AP is up).
- **Concurrent mode fallback.** Try live join with both hotspot and managed mode on the chip. If the hardware doesn't support it after 60s, drop hotspot and retry join alone.
- **60s rollback.** When joining a saved network from Settings, if unreachable after 60s, revert to the previous network.
- **5-minute fallback.** If saved Wi-Fi unreachable for 5 minutes (check every 30s), bring hotspot back.
- **Country code:** always start with `US` (regulatory domain 00). Fetch `CF-IPCountry` from domain service on successful boot/IP-report. Persist to `/etc/environment` or `.env`. Run `iw reg set <cc>` before next hotspot.
- **Validation:** validate SSID (≤32 bytes UTF-8, no null) and password (8–64 bytes UTF-8, no shell metacharacters). Never pass credentials through shell; use nmcli programmatically.
- **Setup password in image:** baked into the Dockerfile or `.env.example`.
- **Host privileged code location:** systemd service + socket at `/run/tskfrce-wifi.sock`. No Docker-side privilege escalation.
- **Unit tests:** mock nmcli completely. No real Wi-Fi access.
- **Mockups:** phone-sized HTML at `docs/mockups/box-lifecycle/captive-setup.html` and `docs/mockups/box-lifecycle/settings-wifi.html`. Match existing v2 UI style (light and dark).
- **Files:** stay under 500 lines each.
- **Ruff:** `ruff format --check backend && ruff check backend`.
- **Commits:** semantic, ending with `Co-Authored-By: Claude Haiku 4.5 <noreply@anthropic.com>`.

- [ ] **Acceptance:** Running twice is safe. On beta box, `nmcli d` shows eno2 in "connected" state and Wi-Fi in "disconnected" or "unmanaged".

## Task 2: Backend Wi-Fi API routes

- [ ] **Files:** Create `backend/app/api/network.py`, Create `backend/app/services/network_wifi.py`
- [ ] **Routes:**
  - `POST /api/network/wifi/scan` → calls service, returns `{networks: [{ssid, signal, security}, ...]}` sorted by signal strength. Cached for 30s if called repeatedly.
  - `POST /api/network/wifi/join` → `{ssid, password, timeout: 60}` → starts async join, returns `{status: "joining"}`. Polls status until done or timeout.
  - `GET /api/network/wifi/status` → `{connected: bool, ssid: str | null, signal: int, country: str}`
  - `POST /api/network/wifi/forget` → forgets the saved network.
  - `POST /api/network/country` → `{country: str}` → for IP-mode boxes to set country code.
- [ ] **Service layer:** abstracts nmcli calls. Single source of truth for Wi-Fi logic.
- [ ] **Constraint:** never run nmcli commands directly in routes. All via service.
- [ ] **Acceptance:** routes return JSON, no shell injection vectors. Validation rejects invalid SSIDs/passwords before nmcli.

## Task 3: Host-side nmcli wrapper (systemd service + Unix socket)

- [ ] **Files:** Create `scripts/tskfrce-wifi-service.sh`, Create `systemd/tskfrce-wifi.service`
- [ ] **What:** A small shell script that:
  - Listens on Unix socket `/run/tskfrce-wifi.sock` (or via systemd socket activation).
  - Reads JSON commands: `{cmd: "scan" | "join" | "status" | "forget", ...}`.
  - Executes nmcli with full validation (no shell eval).
  - Replies with JSON.
  - Runs as root (network privileges).
- [ ] **Commands:**
  - `scan`: `nmcli dev wifi list --rescan no` (uses cached list from boot-time scan).
  - `join`: `nmcli dev wifi connect <ssid> password <password>` (manages the async retry logic).
  - `status`: `nmcli -t -f NAME,STATE dev show` + `iw reg get` for country.
  - `forget`: `nmcli connection delete <ssid>`.
- [ ] **Error handling:** timeouts, busy device, invalid args → JSON error replies.
- [ ] **Constraint:** socket runs as root; backend calls it from inside compose (unprivileged).
- [ ] **Acceptance:** backend can spawn join, poll status, and not block the web server.

## Task 4: Captive portal (DNS spoofing + HTTP server)

- [ ] **Files:** Create `backend/app/api/captive.py`, Modify `backend/app/main.py` to wire it
- [ ] **What:**
  - Respond to `POST /hotspot/config` from setup page with live join status JSON.
  - HTTP captive detection: respond to any HTTP request with a redirect to the captive page or the status JSON.
  - Assume nftables rule (outside Docker, set up by setup-mode systemd unit) spoofs all DNS to box IP.
- [ ] **Responses:**
  - `{status: "joining", ssid}` while join is in progress.
  - `{status: "connected", ssid}` on success.
  - `{status: "error", reason: "wrong_password" | "timeout"}` on failure.
- [ ] **Constraint:** no authentication required (setup mode, before box is claimed).
- [ ] **Acceptance:** phone captive pop-up shows "Connected!" or "Wrong password" without app signing in.

## Task 5: Setup mode trigger and lifecycle

- [ ] **Files:** Create `systemd/tskfrce-setup-mode.service`, Create `scripts/check-setup-mode.sh`
- [ ] **What:**
  - On boot, `check-setup-mode.sh`:
    - Check if eno2 has a DHCP lease.
    - Check if a saved Wi-Fi connection exists in nmcli.
    - If neither, start setup mode (enable hotspot, captive portal).
  - Setup mode stays on until online (either wired or Wi-Fi join succeeds).
  - If saved Wi-Fi is unreachable for 5 minutes (polled every 30s), bring hotspot back.
- [ ] **Constraint:** setup mode is re-triggerable if Wi-Fi drops (idempotent).
- [ ] **Acceptance:** unplug wired, box starts hotspot. Plug in wired or join Wi-Fi, hotspot stops.

## Task 6: Country code handling

- [ ] **Files:** Modify `backend/app/api/network.py`, Create `backend/app/services/network_country.py`
- [ ] **What:**
  - Read domain service IP-report reply (when boot or IP-report endpoint is called).
  - Extract `CF-IPCountry` header (e.g., "US", "GB").
  - Save to `/etc/environment` as `TSKFRCE_COUNTRY=<cc>`.
  - Call `iw reg set <cc>` via host service (systemd script).
  - For IP-mode boxes: Settings → Wi-Fi has a country dropdown (stored in family settings).
- [ ] **Constraint:** domain-connected boxes only. IP-mode boxes use Settings dropdown.
- [ ] **Acceptance:** on first online boot, hotspot becomes `<cc>` channel-capable. Regulatory domain is no longer `00`.
